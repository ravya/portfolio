Monolith to Microservices Migration

Zomato • 2024-2025
Domain-Driven Design Go Distributed Systems Team Leadership

Challenge

Led the Cart and Order Management charter to transform a tightly-coupled PHP monolith into a distributed microservices architecture. The system processed millions of orders daily, and any migration needed to maintain service quality while enabling faster development velocity and better scalability.

Solution & Leadership

Spearheaded the migration strategy using domain-driven design principles, leading a team of 10-15 engineers through this transformation.

  • Applied domain-driven design to identify bounded contexts and design service boundaries around business capabilities
  • Architected distributed system with clear service ownership: Cart Service, Order Service, Promo Service, Payment Service
  • Implemented strangler fig pattern for gradual migration, ensuring business continuity throughout
  • Built comprehensive observability stack for distributed tracing and debugging across services
  • Led team through architecture decisions, code reviews, and technical mentorship

Technical Architecture

  • Introduced event-driven architecture using Kafka for async communication between services
  • Implemented API gateway pattern for routing, authentication, and rate limiting
  • Designed distributed tracing with correlation IDs for end-to-end request tracking
  • Built centralized configuration management and service discovery
  • Created CI/CD pipelines enabling independent service deployments
  • Implemented circuit breakers, retries, and fallback mechanisms for resilience

Operational Excellence

  • Implemented structured on-call workflows with clear escalation paths
  • Built automated Slack alerting system improving Mean Time to Resolution (MTTR)
  • Established SLOs and monitoring dashboards for each microservice
  • Created runbooks and incident response procedures
