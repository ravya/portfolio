Multi-Tenant Infrastructure Architecture

Zomato • 2023-2024
Go Microservices Multi-Tenancy AWS

Challenge

Integrate two separate food delivery platforms while maintaining distinct brand identities and enabling future integrations. The existing infrastructure wasn't designed for multi-tenancy, and with systems handling up to 80,000 requests per second during peak traffic, any downtime would impact millions of daily orders.

Solution & Leadership

I led the engineering team that architected and implemented the company's first multi-tenant infrastructure. This was a company-wide initiative, and my team pioneered the approach that later became the standard for all integrations.

  • Designed tenant isolation at the service layer, enabling separate business rules, pricing, and promotions per brand
  • Architected database partitioning strategy using tenant-aware routing with DynamoDB and MySQL
  • Implemented feature flags and configuration management for tenant-specific behavior
  • Built comprehensive testing framework to validate cross-tenant isolation
  • Led migration of Cart and Order Management services with zero downtime

Technical Deep Dive

  • Introduced tenant context propagation through the entire request lifecycle using Go middleware
  • Implemented tenant-aware Kafka topics and SQS queues for event-driven architecture
  • Created abstraction layers for tenant-specific business logic without code duplication
  • Designed rollback mechanisms and circuit breakers for safe tenant onboarding
  • Built monitoring and alerting per tenant to identify issues in isolation

Monolith to Microservices Migration

Zomato • 2019-2020
Architecture Go PHP Zero Downtime

Challenge

Zomato's order placement flow was tightly coupled in a PHP monolith, causing deployment bottlenecks, making scaling difficult, and slowing down development velocity. With traffic peaks of 80,000 requests per second during high-demand periods and millions of orders processed daily, any migration had to be done with zero downtime and no impact to conversion rates.

Solution & Execution

  • Spearheaded the migration strategy from monolithic PHP application to Go-based microservices
  • Designed service boundaries around business capabilities: Cart Service, Promo Service, Order Service, Payment Service
  • Implemented strangler fig pattern for gradual migration without big-bang rewrites
  • Built feature flags to route traffic between old and new systems for safe rollout
  • Created comprehensive test suites and shadow traffic testing for validation

Technical Architecture

  • Introduced async communication patterns using Kafka for event-driven architecture
  • Implemented API gateway pattern for routing and authentication
  • Designed distributed tracing using correlation IDs for debugging across services
  • Built centralized configuration management and service discovery
  • Created CI/CD pipelines for independent service deployments
  • Implemented circuit breakers and retry mechanisms for resilience

Independent Product: GetExamPix

Full-Stack Product Design Go SaaS

Problem & Opportunity

Students applying for Indian government exams (UPSC, SSC, Banking) face strict image requirements (size, dimensions, file size) that often lead to application rejections. Existing tools were either too complex, required technical knowledge, or didn't maintain image quality.

Solution

  • Built end-to-end web application for intelligent image resizing and compression
  • Implemented smart cropping algorithms that preserve face position and quality
  • Created preset configurations for all major government exam requirements
  • Designed simple, intuitive UI requiring no technical knowledge
  • Deployed production-ready system with CDN integration for fast global access

Technical Stack

  • Backend: Go with image processing libraries for high-performance compression
  • Frontend: Vanilla JavaScript for lightweight, fast user experience
  • Infrastructure: AWS S3, CloudFront CDN, EC2 for hosting
